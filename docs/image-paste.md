# 粘贴进聊天的图片：`[Image 1]`

**你粘贴进看板输入框的图片显示为 `[Image 1]`，而不是长长路径。**同一消息里的下一张是 `[Image 2]`，依此类推；下一条消息重新从 1 计数。发出去的内容换回真实路径，代理照常打开图片。

```
❯ what is wrong here [Image 1] and here [Image 2]
```

## 终端看板上

- **什么会变成图块：**粘贴里的每个图片路径。即 herdr 为剪贴板图片粘贴的路径（`…/herdr-clipboard-images-501/client-327-clipboard-…-0.png`），以及拖进终端的图片文件（`/Users/you/Desktop/Screen\ Shot.png`，或带引号的）。一次粘贴多张出多个图块，夹着文字的粘贴也一样（`<path> also look at <path> here` 进去是 `[Image 1] also look at [Image 2] here`）。图片是结尾为 `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.bmp`、`.heic`、`.tif` 或 `.tiff` 且是本机文件的路径（herdr 自己的照原样处理）。
- **逐键输入的路径**（终端不把粘贴标记为粘贴、而是一个键一个键打进来）：herdr 自己的路径名字一完整就成图块；其它图片路径在后面打一个空格时成图块。
- **保持文字的：**不是图片或本机没这个文件的路径，以及消息里还没有第一张图片时你自己敲的 `[Image 1]`。图块会占用已作为文字存在的名字（输入框里或粘贴里已有键入或粘贴的 `[Image 1]`）的图片保持路径原样，那些文字照原样发出。
- **两侧各留一个空格：**图块从不贴上前后相邻的词或图块，紧跟另一个图块粘贴或输入图片时也一样。
- **算一个字符：**方向键整块跳过图块，其后的退格或其前的删除整块拿掉它，`Ctrl+W` 把它当一个词。光标绝不停在图块内部。撤销（`Ctrl+-`）连图带块恢复。
- **用强调色**，与你的文字区分。
- **按路径发出：**消息发出时每个图块变回路径，与粘贴时一模一样（引号和 `\ ` 也算）。保留的草稿里存的也是路径：草稿回来时（看板重开、文字收起又取回）图块再现。

## 发出之后在聊天里

你在聊天里的消息，终端看板和网页看板上都以图块显示图片，按消息编号：`[Image 1] also look at [Image 2] here`（终端上用强调色）。这对看板发出的路径成立，无论文件在哪（发到另一台机器代理的图片按落点命名），对 Claude Code 在会话记录里为收进的图片写的 `[Image #39]` 也成立。在途的话和会话记录里同样的话只显示一次。

## 网页看板自己的聊天框

网页看板列表下方、网页 UI 没有自己的聊天可显示时用的那个框（[网页看板的聊天框](web-chat-box.md)），对粘贴、拖入或选取的图片同样处理：作为 `[Image 1] ` 进入消息（缩略图照旧显示在消息上方），发出时命名为 `@<path>`，代理就是这样读的。图块在那里也算一个字符：

- **光标绝不停在它里面。**点击、轻点或方向键本要落进内部的，按原方向落在图块前或后；起点或终点在图块内的选区取走整个图块。
- **其后的退格、其前的删除**整块拿掉图片，连同它的贴片；贴片的叉也拿掉图块。
- **图块还是被改动了**（以别的方式被部分剪切）就不再是那张图片：图片被取出，连贴片一起，框上方的条显示 `[Image 1] was taken out of the message.`贴片总意味着图片会被发出。
- **在途时改动的文字**留在框里，照旧；其中已发出的图片以 `@<path>` 站回原位，留下的内容照样点名它。

其它文件仍以 `@<path>` 进入。浏览器里保留的草稿存路径，重新加载后显示路径（贴片那时已消失）。

网页 UI 自己的聊天，多数时候停靠在看板下（[网页看板的聊天](web-chat.md)），归网页 UI：它自己把 `@<path>` 放进输入框。

## 给另一台机器的图片

图片的路径是看板所在机器上的文件。当文字是给另一台机器上的代理或协调者时，看板先把图片发过去，文字按落点命名它，那边的代理才能打开（[你附的文件随文字走](other-machines.md#你附带的文件随你的话走)）。herdr 的剪贴板图片也一样：herdr 把它们保存在其服务器所在的机器上，也就是看板这台。
